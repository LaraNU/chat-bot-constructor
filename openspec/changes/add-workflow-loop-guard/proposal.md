## Why

Движок выполнения (`runWorkflowEngine`) крутит `while (currentNodeId)` без ограничения шагов, а ни валидация, ни канвас не запрещают циклы без ноды ожидания (например, `message A → message B → message A`). Один такой опубликованный цикл заставляет бота слать сообщения в петле до таймаута serverless-функции: спам конечным пользователям, риск бана бота в Telegram и пустая трата compute. Это P1.13 из roadmap и первый пункт M1 («Safe for public beta») плана Q4 2026.

## What Changes

- **Понятие «нода ожидания»** в `entities/workflow`: единый источник истины о типах нод, которые останавливают выполнение и ждут ввода (`question`, `choice`). Используется движком, валидацией и канвасом.
- **Чистые функции анализа графа** в `entities/workflow/lib`: поиск нод, входящих в цикл без ноды ожидания, и проверка, замкнёт ли новое соединение такой цикл.
- **Новая ошибка валидации** `CYCLE_WITHOUT_WAITING_NODE` (severity `error`, по issue на каждую ноду цикла). Блокирует публикацию через существующую клиентскую проверку `validateWorkflow`; сохранение черновика не блокирует.
- **Защита в движке**: повторное выполнение ноды без ожидания в рамках одного update прерывает выполнение; дополнительно действует жёсткий лимит шагов на update. Срабатывание сигнализируется типизированной ошибкой `WorkflowExecutionLimitError`. Защищает уже опубликованные снапшоты и прямые вызовы Server Action.
- **Канвас**: `ReactFlow` получает `isValidConnection`, который запрещает протянуть связь, замыкающую цикл без ноды ожидания.

Нет **BREAKING**-изменений для валидных графов. Уже опубликованные графы с таким циклом перестанут спамить: выполнение прервётся после одного круга.

## Capabilities

### New Capabilities

- `telegram-runtime`: гарантии выполнения опубликованного workflow движком — ограничение выполнения в рамках одного Telegram update.
- `workflow-validation`: правила валидации графа workflow, начиная с запрета циклов без ноды ожидания.

### Modified Capabilities

- `workflow-editor`: канвас запрещает создавать соединения, замыкающие цикл без ноды ожидания.

## Impact

- `src/entities/workflow/model/` — константа типов нод ожидания и type guard.
- `src/entities/workflow/lib/` — новый модуль анализа циклов; `lib/validation/validate-graph-structure.ts` (или новый `validate-cycles.ts` + `validate-workflow.ts`).
- `src/features/telegram-webhook/lib/engine.ts` — защита от циклов и лимит шагов, новая ошибка.
- `src/widgets/workflow-canvas/ui/workflow-canvas.tsx` — `isValidConnection`.
- Тесты: `engine.test.ts`, тесты валидации и анализа графа.
- Документация: `docs/roadmap.md` и `docs/roadmap-ru.md` (статус P1.13); `docs/cursor-context.md`, если там описаны гарантии runtime. Файлов `docs/backend.md` / `docs/frontend.md` в репозитории нет.
- Вне скоупа: серверная валидация публикации (P1.14), fallback-сообщение и сохранение сессии при ошибке движка (P1.16), подсветка ошибок на канвасе и запрет нескольких выходов у линейных нод (P2.11).
